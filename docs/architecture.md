# 系统架构

## 1. 架构原则

工学智链采用“模块化单体 + 可替换外部网关”。核心学习闭环在没有任何外部 API 时仍可运行；模型和搜索只做有证据约束的增强。当前形态便于比赛演示、测试和单机部署，也保留了后续按模块拆分服务的边界。

```text
Vue 3 前端
  └─ REST / HttpOnly refresh cookie
FastAPI 应用
  ├─ API：认证、岗位、路线、画像、知识、会话、学习、证据、集成、评测
  ├─ Domain：目录、JD 解析、画像、路由、检索、生成、编排、评测
  ├─ Infrastructure：数据库、密钥、OpenAI-compatible、联网搜索
  └─ SQLAlchemy / Alembic
       ├─ SQLite（开发与演示）
       └─ PostgreSQL（Docker 生产）
```

## 2. 核心业务闭环

```text
注册/登录
→ 真实情况与方向量表
→ 路线比较与选择
→ 真实 JD 与岗位差距（可选）
→ 本地知识检索（可选联网）
→ 六 Agent 生成与仲裁（可选模型增强）
→ 讲义 / 实操 / 工作样本测评 / 计划
→ 执行本周任务并提交成果、测试与反馈
→ 生成待确认路线版本
→ 用户接受 / 拒绝 / 撤销
→ 画像、计划、报告、消息同步更新
```

六个 Agent 分别为：

| 顺序 | Agent | 可核验输出 |
|---|---|---|
| 1 | 学情建模 Agent | 五态学情、六维能力、技能缺口 |
| 2 | 知识检索 Agent | 检索证据、来源、版本与匹配信息 |
| 3 | 严谨生成 Agent | 依赖优先的候选方案 |
| 4 | 项目生成 Agent | 项目牵引的候选方案 |
| 5 | 仲裁审核 Agent | 候选评分、辩论、融合决定 |
| 6 | 导学交互 Agent | 下一行动、难度调整与追问 |

编排器只负责状态传递和路由，不包装为“第七个 Agent”。事件轨迹保存结构化摘要、证据和耗时，不保存隐藏思维链。

学习计划采用显式版本状态机：系统根据目标岗位、过难、过易、时间不足、持续阻塞或新成果生成 `pending` 版本；只有用户接受后才替换计划阶段。每个版本保存调整前后阶段、原因和可读变更项，支持拒绝和撤销，避免算法暗中改变用户目标。

## 3. 领域数据

`data/computer_domain/catalog.json` 是版本化计算机领域目录，包含三大方向簇、16 个主方向、技能、依赖、诊断题、项目和审核来源；`pathways.json` 提供 29 条可组合的细分技术路线；`career_profiles.json` 提供岗位、工作内容、薪资参考、学历竞争力、市场判断和作品集要求。组合器最多接收 6 条路线，按阶段交错编排并对公共技术去重。`data/evaluation/` 包含 6 个合成学习者和 64 条冻结评测任务，每个主方向 4 条。

## 4. 来源与外部能力

四种来源策略：

1. `knowledge_only`：仅本地审核知识库。
2. `knowledge_web`：本地知识 + 后端联网检索。
3. `knowledge_ai`：本地证据 + AI 个性化整合。
4. `full`：本地、检索、AI、双候选和引用校验。

每次会话保存请求策略、实际策略、来源层、检索时间、知识目录版本、模型信息和降级原因。外部服务失败时保留规则生成结果。

AI 增强结果执行主张级发布闸门：模型输出独立原子陈述、引用标识和逐字证据片段；验证器检查引用存在性、证据片段、数字、技术实体与语义重合。未通过的主张不进入用户可见资源。该自动指标只表示“系统检出的证据不足内容”，真实专业知识谬误率仍需专家盲测逐条标注。

测评采用工作样本而非关键词计分。每题分别采集实施方案、验收验证、失败处理、技术取舍与成果证据；系统检查栏目结构和证据格式，并按证据强度决定画像回写权重。仅有文字方案但没有合格成果证据时生成形成性反馈，不新建虚假的能力画像版本。

## 5. 安全边界

- Access Token 短期使用，Refresh Token 放入 HttpOnly Cookie 并轮换。
- API Key 不进入 localStorage、Agent 轨迹、报告、导出或应用日志。
- 临时密钥仅驻留进程内存；加密密钥使用服务端主密钥。
- 外部地址强制 HTTPS，并对私网、环回、保留地址进行 SSRF 防护。
- 外部服务按用户隔离，受单次 Token、每日请求、每日预算和超时限制。
- 生产治理账号只可通过显式环境变量创建，不提供默认弱口令。

## 6. 部署边界

生产镜像只复制 `backend/app`、Alembic 迁移和领域数据，入口为 `app.main:app`。Nginx 托管前端并代理 `/api/`；PostgreSQL 保存业务数据。外部服务均由用户在运行时配置，不写入镜像或仓库。

新增业务持久化表为 `career_targets`、`evidence_artifacts`、`route_revisions`。本地 SQLite 由启动时的元数据初始化兼容现有演示库；正式升级使用 `002_career_learning_loop` Alembic 迁移，并应在发布前完成 PostgreSQL 升级与回滚演练。
